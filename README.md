# travel2sardinia · travel2sardegna

A bilingual (Italian / English) **information** app for reaching Sardinia's towns. Bosa is the first destination; any other town can join.

It works on two levels:

- **Travellers**: someone in a city with flights to Sardinia chooses their city and sees how to reach each participating town, where to stay there and what's on through the year. A date is optional and adds exact connections.
- **Local organisations**: in each town, businesses, authorities and cultural groups keep their town's page current through a WhatsApp coordination group and a local coordinator.

There are no prices and no bookings: every action is a link out to the provider (airline search, ARST, Trenitalia, Hodlstay, the organiser's website).

## Choosing a city

- **Phones**: a search box. Typing part of a city, an airport code or a country (in Italian or English, accents optional) shows matching cities grouped by country.
- **Tablets and computers**: the search box, plus clicking any city on the map. "All routes" zooms out to show every city.
- **No direct flight**: if nothing matches (e.g. "Birmingham"), the app says so, offers the countries that do have direct flights, and lists Italian airports with year-round flights to Sardinia for connecting.

## Domains

- **travel2sardinia.com**: the main address (Settings → Pages → Custom domain).
- **travel2sardegna.com**: set a redirect at the registrar to `https://travel2sardinia.com/?lang=it`, so Italian speakers arriving via the Italian name get Italian.

The app also picks the language from the domain: `…sardegna…` → Italian, `…sardinia…` → English. A visitor's own choice (the IT | EN toggle, or `?lang=`) always wins and is remembered.

## Structure

```
index.html                     island home: flights, destinations, public holidays
<town>/index.html              town page: flights, getting there, stays, events, tips
<town>/organisations/          page for the town's organisations (join the coordination group)
organisations/                 island page: how a town joins
app.js · i18n.js · style.css   shared by every page
templates/                     page templates used for new towns
data/                          all content (JSON), edited in /admin
admin/                         Sveltia CMS (config generated by scripts/cms_config.py)
scripts/                       timetable build, new town, admin config
```

### Island data, shared by every town

| File | What it holds |
|---|---|
| `data/flights.json` | Seasonal route table to AHO / CAG / OLB (periods and days of the week) |
| `data/holidays.json` | National and regional public holidays (with holiday-timetable flags) |
| `data/destinations.json` | The towns: name, description, map position, airports, published |
| `data/info.json` | Island-wide tips |
| `data/site.json` | Titles, airports, operator links, contact for towns that want to join |
| `data/transit-config.json` | GTFS feeds, stop patterns and airport → town routes, per town |
| `data/transit.json` | Generated weekly by the workflow. Don't edit it |

### Town data: `data/destinations/<town>/`

| File | What it holds |
|---|---|
| `events.json` | Local events and the town's own holidays (e.g. patron saints), each with an optional website button |
| `stays.json` | Places to stay, with Hodlstay links |
| `info.json` | Local tips |
| `destination.json` | Hodlstay links and the coordinator's contact link |

## Updating flights (Alghero and Olbia)

Both airports publish every flight on one page, with a toggle to choose the airport: aeroportodialghero.it → Voli → Tutti i voli (Alghero), and the same page on geasar.it (Olbia).

1. On a phone, open the list for the airport with **Arrivals** and **Type of flight: Line**. Scroll to the bottom so every flight loads.
2. Save the page (Chrome: ⋮ → ⬇). Rename the `.mhtml` file to `.txt`.
3. Import it:
   ```sh
   python3 scripts/import_airport_page.py saved-page.txt            # unpublished, to review in /admin
   python3 scripts/import_airport_page.py saved-page.txt --publish  # or publish straight away
   ```
   This replaces that airport's previously imported routes and keeps everything else. It drops periods that have already ended, takes the arrival time (moving flights that land after midnight to the next day), and reports any new airport code to add to `data/airports-ref.json`.

Do this at the start of each season (end of March, end of October) and when new routes are announced. Cagliari's site isn't in this format yet.

## Adding a town

1. Run the script with the town's name, position and the airports people use to reach it:
   ```sh
   python3 scripts/new_destination.py cuglieri --name Cuglieri --province Oristano \
       --lat 40.187 --lon 8.568 --airports AHO,CAG
   ```
   It creates the town page, its organisations page and empty data files, adds the town to `data/destinations.json` **unpublished**, and rebuilds the admin.
2. Set up the bus and train route in `data/transit-config.json`: add any new `segments` (stop-name patterns) and the town's `chains` per airport. Then run the *Update timetables* workflow and check `matched_stops` in `data/transit.json`.
3. In `/admin`, fill in the description, first events and coordinator link, then tick **Published**.
4. Commit and push. The site redeploys itself.

## Editing (admin)

`/admin` opens [Sveltia CMS](https://github.com/sveltia/sveltia-cms) with one section for the island and one per town. Every save is a commit, and the site redeploys.

Editors need write access to the repo and a fine-grained personal access token (Contents: Read and write, this repo only). They choose *Sign in with token*. Everyone with access can technically edit every town; by agreement each coordinator edits only their own town, and every change is recorded in the history. If many towns join, a later step is one repo per town.

## One-time setup

1. **Pages**: Settings → Pages → Source: **GitHub Actions**. Then add the custom domain `travel2sardinia.com` and follow GitHub's DNS instructions.
2. **Timetables**: Actions → *Update timetables* → **Run workflow**. Check `matched_stops` in `data/transit.json`, adjust patterns in `data/transit-config.json` if needed, and run it again.
3. **Coordination**: see [COORDINATION.md](COORDINATION.md).

## Local development

```sh
python3 -m http.server 8000      # then open http://localhost:8000
python3 tests/make_fixture.py /tmp/fix && python3 scripts/build_transit.py --local /tmp/fix --start 2027-01-01 --out /tmp/transit.json
python3 scripts/cms_config.py    # rebuild admin/config.yml after editing admin/fields.yml
```

The fixture feeds in `tests/` are invented test data and are never published.

## Data sources

- Bus and rail timetables: ARST, Trenitalia and ASPO GTFS open data (mirrors via the Mobility Database).
- Map: © OpenStreetMap contributors. Leaflet 1.9.4 is bundled in `vendor/`.
- Flight routes: entered by hand from the airports' published destination lists.
